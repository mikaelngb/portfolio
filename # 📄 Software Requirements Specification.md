# 📄 Software Requirements Specification (SRS) - Professional Portfolio

## 💻 System Design

The system will be a high-performance **Single-Page Application (SPA)** built with React and statically generated by **Next.js**.

-   **Architecture Goal:** Prioritize speed and maintainability by using a static output, perfect for free, reliable hosting.
-   **Content Management:** All professional data will be stored in simple, dedicated **static data files** (JSON, Markdown/MDX). This fulfills the requirement for **easy, manual content updates (FR.05)** without needing a database or CMS.
-   **Hosting:** The final static assets (`HTML`, `CSS`, `JS`) will be deployed to **GitHub Pages (FR.04)** via Next.js's `output: 'export'` configuration.

---

## 🏗️ Architecture Pattern

| Pattern                          | Description                                                                                                                                                        |
| :------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Component-Based**              | Using **React** to build reusable UI components (e.g., `ProjectCard`, `SkillMeter`, `TimelineItem`).                                                               |
| **Static Site Generation (SSG)** | **Next.js `output: 'export'`** will pre-render all pages at build time. This delivers the fastest load times and eliminates server-side dependencies.              |
| **Styling Strategy**             | **Utility-First CSS (Tailwind CSS)** combined with highly accessible, pre-styled components from **Shadcn UI** for rapid development and consistent visual appeal. |

---

## 🧠 State Management

-   **Global State:** Not Required.
-   **Method:** **Local/Component State** (using React's `useState`). Since the site is static, state will only manage minor UI features like a mobile menu toggle, dark mode (if implemented), or hover/focus effects.
-   **Data Source:** All core portfolio content is sourced from **static data imports** during the Next.js build.

---

## 🌊 Data Flow

1.  **Input:** Developer updates simple data files (`/data/`, `/content/`) with new projects, experience, or skills (**FR.05**).
2.  **Build:** Developer runs `next build` (using `output: 'export'`). Next.js uses React components and the static data to generate the final `out/` directory.
3.  **Deployment:** The `out/` directory content is pushed/deployed to the **GitHub Pages** hosting branch.
4.  **Recruiter Access:** Recruiter navigates to the GitHub Pages URL.
5.  **Output:** The browser loads the pre-rendered, optimized HTML, immediately displaying the full, responsive portfolio (**FR.01**, **FR.06**).

## 🔑 Authentication Process

-   **Status:** Not Applicable.
-   **Reason:** This is a public, read-only portfolio site intended for recruiters and professional contacts. No user accounts, login, or authentication is required.

---

## 🗺️ Route Design

The site uses a single-page structure leveraging client-side routing (anchor links) for navigation. A dedicated PDF file is mandatory.

| Route                | Function & Content                                                                                                              | Requirements Mapping          |
| :------------------- | :------------------------------------------------------------------------------------------------------------------------------ | :---------------------------- |
| **`/`**              | **Home:** The single, scrollable page containing all portfolio sections (Header, About, Skills, Experience, Projects, Contact). | **FR.01 (Display All Info)**  |
| **`/#<section_id>`** | **Internal Link:** Uses client-side anchor links to jump to specific sections of the single page.                               | **FR.03 (Navigation)**        |
| **`/resume.pdf`**    | **Direct Asset:** A direct link to the stored PDF file of the resume.                                                           | **FR.02 (Resume Management)** |

---

## 📡 API Design

-   **Status:** Not Applicable.
-   **Reason:** As a static site, all content is embedded during the build phase. There is no need for a dynamic backend or API endpoints to serve the core portfolio data.

---

## 🗄️ Database Design ERD

-   **Status:** Not Applicable.
-   **Reason:** The system uses **static files (JSON/MDX)** for data persistence instead of a database, aligning with the requirements for static hosting and easy content updates.

### Recommendation Action

Given that you are ready to start development with **Next.js, Tailwind CSS, and Shadcn UI**, your next step should be setting up the project for static export and content configuration.

| Priority                    | Action Item                                                     | Detail                                                                                                                                                                       |
| :-------------------------- | :-------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. 🚀 Project Setup**     | Initialize the Next.js project and configure for static export. | In `next.config.js`, set `output: 'export'`. Also, configure the `basePath` if deploying to a sub-directory (common for GitHub Pages, e.g., `/your-repo-name`).              |
| **2. 🎨 UI/Styling Setup**  | Set up Tailwind CSS and initialize Shadcn UI.                   | Install Tailwind and then run `npx shadcn-ui@latest init` to configure components, which will be essential for the professional, high-contrast design.                       |
| **3. 🧱 Content Structure** | Create the dedicated data structure for content updates.        | Create a `/data` folder with files like `experience.json`, `projects.json`, and `skills.json` to store all professional information, ensuring **FR.05** is met from day one. |
